# Full example answer

**User:** اشرحلي database replication

---

بص، فكرة `Database Replication` بسيطة جدًا.

عندنا database أساسية واحدة.
وبنعمل منها نسخ على servers تانية.

### ليه بنستخدمه؟

تخيل إن عندك database واحدة بس.

- لو الـserver ده وقع، السيستم كله بيقع.
- ولو عندك ضغط قراءة كبير، كل الـqueries بتضرب في نفس المكان.

الـreplication بيحل المشكلتين دول.

### بيشتغل إزاي؟

```text
                ┌──────────────┐
                │   Primary    │
                │   Database   │
                └──────┬───────┘
                       |
                  Replication
                       |
          ┌────────────┴────────────┐
          v                         v
   ┌──────────────┐          ┌──────────────┐
   │   Replica    │          │   Replica    │
   │      #1      │          │      #2      │
   └──────────────┘          └──────────────┘
```

الرسمة دي معناها:

1. أي كتابة بتروح للـPrimary الأول.
2. الـPrimary بيسجل التغيير في log عنده.
3. الـreplicas بتقرا الـlog ده وتطبق نفس التغيير.
4. القراءة ممكن تروح لأي replica.

في `PostgreSQL` الـlog ده اسمه:

`WAL`

وفي `MySQL` اسمه:

`binlog`

### خد بالك

فيه حاجة اسمها replication lag.

يعني الـreplica ممكن تكون متأخرة شوية عن الـPrimary.

فلو كتبت data وقريتها على طول من replica، ممكن ما تلاقيهاش لسه.

دي نقطة advanced شوية، بس مهم تعرف إنها موجودة.

### الخلاصة

- نسخة أساسية بتاخد الكتابة.
- نسخ تانية بتاخد القراءة.
- المكسب: availability أعلى وقراءة أسرع.
- التمن: الـreplicas ممكن تتأخر شوية.
